# P0.10 — Workspace / Content Slot

Status: **FINAL VERIFIED — CONCRETE SLICE SPECIFICATION**

1. Identity: P0.10; Workspace/Content Context.
2. Objective: establish operational workspace and production Content Slot boundary.
3. Scope: membership, content plan/slot, revision, lock/archive, autosave. Out: Planner-owned commands and Research ownership.
4. Sources: Core Contract #9; Phase 4 SoT; Planner authority; implementation specification.
5. Dependencies: P0.02 authorization; P0.09 events; P0.13 Planner.
6. Architecture: Workspace is operational context; Content Slot is production anchor; Content Context owns slot state.
7. Ownership: Workspace/Content Context owns slot lifecycle and revision state.
8. Data model: workspace membership, content plan, slot, revision, lock/archive and autosave metadata per Contract #9.
9. State: draft/active → revised/locked/archived as approved; stale revision must not silently overwrite.
10. API: create/update/lock/archive/revision/autosave operations through Content Context application boundary.
11. UI: workspace, planner/calendar and slot editing states including loading, conflict, locked and archived.
12. Events: approved slot/revision lifecycle events through P0.09.
13. Workers: autosave/event work may be asynchronous and must be retry-safe.
14. Security: membership/scope authorization server-side; lock is enforced server-side.
15. Configuration: approved autosave/retention settings only.
16. Storage: canonical slot/revision data persisted; media is Storage-owned.
17. Observability: workspace/slot/revision/correlation identifiers.
18. Errors: permission denied, stale revision, locked/archived mutation and validation errors use canonical classes.
19. Idempotency: autosave/revision commands prevent duplicate or stale overwrite.
20. Tests: create, permission, autosave, refresh/login recovery, revision conflict and lock enforcement.
21. Acceptance: Content Slot state has one authority and Planner cannot directly mutate its repository.
22. Gate: ownership, lifecycle, authorization and revision semantics verified before build.
23. Checklist: [ ] membership [ ] slot lifecycle [ ] revision [ ] lock [ ] autosave [ ] tests.
24. Exit: context boundary locked.
25. Risks: stale writes and cross-workspace access.
26. Open Decisions: none introduced.
