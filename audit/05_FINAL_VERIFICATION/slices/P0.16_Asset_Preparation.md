# P0.16 — Asset Preparation Core

Status: **FINAL VERIFIED — CONCRETE SLICE SPECIFICATION**

1. Identity: P0.16; Asset Preparation.
2. Objective: prepare/generate approved assets while enforcing entitlement and provider boundaries.
3. Scope: asset project/requirement, generation job, upload, preview/final generation, provider routing, retry, version, approval and entitlement consumption.
4. Sources: Asset Preparation addendum; Entitlement; Storage; production pipeline.
5. Dependencies: P0.05 entitlement; P0.08 storage; P0.15 blueprint; P0.09 events.
6. Architecture: Asset Preparation owns generation workflow; provider adapter does not own business state.
7. Ownership: asset requirement/version/generation job and approval state; Storage owns object lifecycle.
8. Data model: asset project/requirement, generation job, provider reference, asset version, approval and entitlement usage record.
9. State: requested → generating → preview/final → approved/failed with retry semantics from authoritative lifecycle rules.
10. API: create requirement, generate, upload, preview/finalize, approve and retrieve asset operations.
11. UI: generation progress, preview, approval, failure/retry and usage states.
12. Events: approved generation/asset lifecycle events via P0.09.
13. Workers: generation job worker with retry/DLQ and provider isolation.
14. Security: entitlement and authorization checked server-side before consumption/provider use.
15. Configuration: provider routing and generation configuration follow approved rules.
16. Storage: uploaded/generated objects are Storage-owned; asset business state remains here.
17. Observability: generation job/provider/asset/version/correlation identifiers.
18. Errors: provider failure, entitlement shortage, invalid blueprint and generation failure are explicit.
19. Idempotency: retryable generation and entitlement consumption must not duplicate usage.
20. Tests: blueprint acceptance, entitlement check, provider call, duplicate protection, retry and usage accounting.
21. Acceptance: approved generation consumes entitlement exactly once and preserves provider trace.
22. Gate: provider, entitlement and storage boundaries verified.
23. Checklist: [ ] requirement [ ] job [ ] provider [ ] entitlement [ ] retry [ ] version [ ] tests.
24. Exit: asset preparation core locked.
25. Risks: duplicate generation or usage accounting error.
26. Open Decisions: none introduced.
