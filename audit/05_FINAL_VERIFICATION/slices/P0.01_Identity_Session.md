# P0.01 — Identity / Session

Status: **FINAL VERIFIED — CONCRETE SLICE SPECIFICATION**

1. Identity: P0.01; Identity/Session.
2. Objective: account registration, login, session lifecycle, logout, refresh, revocation and server-enforced single-login.
3. Scope: account/session journey. Out: commercial entitlement and authorization ownership.
4. Sources: Core Contract #1; Final PRD; Phase 4 SoT; Slice Order/Roadmap.
5. Dependencies: P0.00 architecture; P0.02 authorization consumes identity state.
6. Architecture: authentication is server-side; downstream authorization reads identity/session context.
7. Ownership: User, Account Status and Session; Permission remains Authorization-owned.
8. Data Model: user/account identity, account status and session/revocation records per Contract #1.
9. State Machine: active/revoked/suspended/blocked outcomes as defined by Contract #1.
10. API/Application Contract: register/create account, login, refresh, logout and revoke session.
11. UI/UX Scope: registration/login/logout/session states including loading, invalid credentials, suspended/blocked, success and revoked.
12. Event Contract: approved identity events such as UserCreated/LoginSucceeded through P0.09.
13. Worker/Job Scope: no mandatory worker; session operations are synchronous unless contract specifies otherwise.
14. Security/Authorization: authentication and single-login enforced server-side; credentials/secrets protected.
15. Configuration: approved authentication/session configuration only.
16. Storage: persist account/session state according to Contract #1.
17. Observability: request/correlation/session identifiers without secrets.
18. Error Handling: invalid credentials, blocked/suspended account, revoked session and validation errors.
19. Idempotency/Concurrency: session revocation is retry-safe; concurrent login/session rules follow Contract #1.
20. Test Specification: login/logout/refresh/persistence/second-device revocation/suspended-blocked accounts.
21. Acceptance Criteria: identity journey works and revoked/blocked sessions cannot authenticate.
22. Acceptance Gate: authentication authority verified before protected slices build.
23. Implementation Checklist: [ ] account [ ] login [ ] session [ ] refresh [ ] logout [ ] revoke [ ] tests.
24. Exit Conditions: identity journey locked.
25. Known Risks: session leakage or incorrect revocation.
26. Open Decisions: none introduced.
