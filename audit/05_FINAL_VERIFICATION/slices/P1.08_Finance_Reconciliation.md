# P1.08 — Finance / Reconciliation

Status: **FINAL VERIFIED — CONCRETE SLICE SPECIFICATION**

1. Identity: P1.08; Finance/Reconciliation.
2. Objective: reconcile provider/payment records without silently changing financial truth.
3. Scope: financial reconciliation, provider mismatch investigation and controlled correction of financial state.
4. Sources: Payment authority; Provider reconciliation boundary; Referral boundary; Phase 4 SoT.
5. Dependencies: P0.06 Payment; P0.09 events; P1.07 Referral where financial consequences are referenced.
6. Architecture: reconciliation is controlled application workflow; Payment remains financial owner.
7. Ownership: reconciliation case/resolution record; not independent financial truth.
8. Data model: internal financial reference, provider reference, amount/currency comparison, mismatch and resolution audit.
9. State: unresolved/needs reconciliation → investigated → resolved according to approved policy.
10. API: query mismatch, investigate, resolve/reconcile with privileged authorization.
11. UI: mismatch queue, evidence, resolution and audit states.
12. Events: consumes provider/payment events; resolution is auditable.
13. Workers: provider reconciliation jobs may be asynchronous and retry-safe.
14. Security: privileged finance actions require server authorization and audit.
15. Configuration: approved reconciliation thresholds/rules only.
16. Storage: reconciliation records persist; source financial state remains Payment-owned.
17. Observability: payment/provider/reference/correlation identifiers.
18. Errors: amount/currency/reference mismatch and unresolved provider outcomes remain explicit.
19. Idempotency: resolution operations are duplicate-safe.
20. Tests: amount/currency/reference matching, mismatch investigation, audit trail and idempotent resolution.
21. Acceptance: ambiguous provider outcomes never silently become success/failure.
22. Gate: Payment ownership and Entitlement reversal separation verified.
23. Checklist: [ ] mismatch [ ] investigation [ ] resolution [ ] audit [ ] idempotency [ ] tests.
24. Exit: reconciliation boundary ready.
25. Risks: manual correction could create inconsistent financial state.
26. Open Decisions: none introduced.
