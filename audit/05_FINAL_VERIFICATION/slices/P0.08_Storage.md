# P0.08 — Storage

Status: **FINAL VERIFIED — CONCRETE SLICE SPECIFICATION**

1. **Identity:** P0.08; Storage; P0.
2. **Objective:** authoritative object lifecycle for upload, access, retention and purge.
3. **Scope:** StorageObject, upload session, commit, authorized download, signed URL, retention, purge and adapter.
4. **Sources:** Core Contract #7; implementation roadmap; Phase 4 SoT.
5. **Dependencies:** P0.00 architecture; P0.02 authorization; P0.09 events; downstream Editor/Export/Support.
6. **Architecture:** Storage owns object lifecycle; consuming domains own business meaning and parent state.
7. **Ownership:** StorageObject, upload/commit and purge lifecycle are Storage-owned.
8. **Data model:** object, upload session, ownership/scope, retention, purge state and adapter reference per Contract #7.
9. **State:** upload → committed → retained → purge requested → purged or PURGE_FAILED/retry; parent business context survives purge failure.
10. **API:** upload/create session, commit, authorized download/signed URL, retention/purge operations.
11. **UI:** upload progress, success, access denied, missing/expired object and retry states where surfaced.
12. **Events:** StoragePurged and approved storage lifecycle events via P0.09.
13. **Workers:** purge/retry worker required for asynchronous deletion; exhausted failures follow retry/DLQ authority.
14. **Security:** ownership, tenant/scope authorization and signed access are server-enforced.
15. **Configuration:** retention values follow approved policy; Export/Editor media 48h and Support attachments 90 days after Closed per roadmap.
16. **Storage:** provider adapter is implementation detail; business state remains outside provider.
17. **Observability:** object reference, parent context, purge attempt and correlation identifiers; no secrets.
18. **Errors:** upload/commit/access/purge errors are classified; PURGE_FAILED is recoverable.
19. **Idempotency:** commit and purge/retry must be safe under duplicate requests.
20. **Tests:** upload, commit, ownership, download, retention, purge, failure/retry and parent-content survival.
21. **Acceptance:** authorized objects are retrievable, retention is enforced, purge failure is retryable and parent business state survives.
22. **Gate:** lifecycle, authorization and provider boundary verified before build.
23. **Checklist:** [ ] object lifecycle [ ] access [ ] retention [ ] purge worker [ ] retry/DLQ [ ] tests.
24. **Exit:** storage lifecycle locked.
25. **Risks:** premature deletion or cross-scope access can cause data loss/privacy breach.
26. **Open Decisions:** none introduced.
